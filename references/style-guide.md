# style-guide — 写作风格规范

## 标题规范

- 使用 emoji 开头，增加视觉层次：`🚀 快速开始`、`📋 配置项`、`💡 使用示例`
- 避免标题过长，保持简洁有力
- 使用 `##` 和 `###` 分级，避免更深嵌套

## 语言风格

- 专业但不生硬，像真人写的
- 避免"毫无疑问"、"众所周知"等废话
- 每句话都有信息量
- 英文为主，中文辅助（可中英双语）

## 代码块规范

- 所有代码块必须标注语言：`bash`、`javascript`、`python` 等
- 代码示例必须可以直接运行
- 避免"示例代码，仅供参考"
- 关键行添加注释说明

## 列表规范

- 使用 `-` 而非 `*` 或数字
- 每条以动词开头
- 避免空洞描述，要有具体信息

**好的列表：**
- 3 种预设主题：深色、浅色、高对比
- 支持 12 种输出格式：PDF、Markdown、HTML 等
- 自动检测编码，避免乱码

**差的列表：**
- 功能强大
- 易于使用
- 高效稳定

## 表格规范

- 每列必须有表头
- 每一行都要有描述
- 默认值列用 `默认值` 标注
- 参数类型使用标准类型：`string`、`boolean`、`number`、`array`

## 文档结构

按以下顺序排列章节：

1. 项目标题 + 徽章
2. 一句话介绍
3. 功能演示（占位符提示用户补充）
4. 核心功能（3-5 项）
5. 快速开始
6. 详细使用说明
7. 配置项（表格）
8. 使用示例（至少 3 个）
9. 项目结构
10. 贡献指南
11. License

## 自检清单

生成后检查：

- [ ] 所有代码块有语言标注
- [ ] 安装步骤可一步步跟随
- [ ] 无"TODO"或空白占位符（除媒体外）
- [ ] 配置表格每行有默认值
- [ ] 没有"仅供参考"类表述
- [ ] 代码示例可复制运行
